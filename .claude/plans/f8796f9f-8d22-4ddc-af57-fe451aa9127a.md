## Webhook note (deferred, record in docs)
SEARCH_MANAGE_WEBHOOKS is present (GET /v3/searches/{id}/webhooks -> 200).
Payload carries ONLY search status, not watchlist readiness, and our search returns
status=complete while watchlist is_processing is still true. So a status webhook fires at a
moment we already know about; in production pair it with the is_processing check rather than
replacing it. GET exposes triggered_count / last_triggered_at, which proves firing without
inbound reachability. Needs a public HTTPS URL, which localhost does not have.
